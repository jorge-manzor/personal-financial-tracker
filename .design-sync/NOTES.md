# design-sync notes — @zendo/design-system

## Repo shape

`personal-financial-tracker/frontend` is the real app (Vite SPA, `tsconfig.app.json` has
`noEmit: true`, no `main`/`module`/`exports`) — it is NOT a design-system package and cannot
be synced directly. `frontend/design-system/` is a separate, additive package created
specifically for this sync: ~40 presentational components hand-extracted from
`frontend/src/*.tsx`, decoupled from API calls / router / app context, with their own
`package.json`, `tsup` build (emits `dist/index.js` + `dist/index.d.ts`), and a real compiled
Tailwind stylesheet (`dist/styles.css`, generated via `@tailwindcss/cli` scanning
`frontend/design-system/src/**/*.tsx` — see `build:css` script in that package's
`package.json`).

**`frontend/design-system/` is a fork, not a shared source of truth.** Editing a component in
the real app (`frontend/src/`) does NOT update its design-system twin. Re-extraction is manual.

## Known render warns (triaged, not new issues to chase)

- All 17 bare icon components (`IconPencil`, `IconTrash`, `IconBank`, etc.) plus
  `BankingBalanceScopeHelpButton` show `[RENDER_THIN]`/`[RENDER_BLANK]` on the floor card —
  expected: they're small SVGs/icon-only triggers with no authored preview (out of scope for
  this sync's "core 20"). Not broken; authorable on any future re-sync.
- `PanelSectoresTab`: the `Default`/`Dark` cells' donut `<Pie>` renders as a thin sliver in the
  static capture (legend renders fine). Root cause: `PanelSectoresTab.tsx` hardcodes
  `<Pie isAnimationActive>` with no prop to disable the mount animation, and the capture
  pipeline screenshots before recharts' animation settles. Reproduced consistently across
  3 rebuild/recapture attempts, independent of container width. NOT fixable from the preview
  alone — would need a small source change (expose a `disableAnimation`/`isAnimationActive`
  prop, or default it to `false`) to `frontend/design-system/src/PanelSectoresTab.tsx`. Left
  as `needs-work` for those 2 cells; `Empty` cell grades `good`.

## Re-sync risks

- The Tailwind CSS (`dist/styles.css`) is regenerated by scanning `frontend/design-system/src/`
  for class names actually used — if a re-extraction adds a component using a Tailwind class
  not seen anywhere else in the package, re-run `npm run build` (in `frontend/design-system/`)
  before re-running the converter, or the new classes won't have compiled rules.
- `overrides` in `.design-sync/config.json` (`cardMode`/`primaryStory` for
  `BankingConfirmDialog`, `BankingDatePicker`, `IconMenuButton`, `SyncOverlay`,
  `PanelSectoresTab`, `PortfolioChart`) exist because these are portal/dialog/wide-chart
  components — don't remove them without re-checking `[GRID_OVERFLOW]` warnings.
- `BankingDatePicker` and `IconMenuButton` have no `open` prop (open/close is internal
  `useState`) — their authored previews (`.design-sync/previews/BankingDatePicker.tsx`,
  `IconMenuButton.tsx`) work around this with a small wrapper that auto-clicks the trigger via
  `useEffect` on mount, to force the portal content open for the screenshot. If either
  component's internal open logic changes, that wrapper may need adjusting.
- This sync only covers 20 of the ~40 components with authored previews (the "core" set); the
  rest (icons + `BankingBalanceScopeHelpButton`) intentionally ship on the floor card — a
  reasonable incremental-authoring target for a future re-sync.
- No `.d.ts`/docs source exists to auto-match per-component docs (`docs: 0/40 components
  matched` in the build log) — every `.prompt.md` is synthesized from the `.d.ts` props + the
  authored preview. This is expected for this package (it has no docs site).
